## How to use this file

- **Never delete or cross out an item.** Mark it `[DONE]` and leave the text intact.
- IDs are permanent names, referenced in conversation ("do TODO-17"). Never renumber, never reuse.
- New items go at the **end of the topical section** they belong to, with the next free ID. IDs will stop being contiguous within a section; that is expected.
- **Anything found open goes in here, always.** A loose end noticed during other work (gap, stale comment, deferred cleanup, out-of-scope thing) gets an item saying what was found, why it was not done, and what deciding it needs. Reporting a finding is not recording it.
- **Adding an item or changing its status is two edits**: the item heading and its Index row (plus the Still open list if it crossed that line). Take the next free ID from the items, not from the line below.
- Feature-list **Extras** start as `[POSTPONED]`: deliberately deferred until the MVP is validated.

**Status legend:** `[ ]` not started · `[~]` in progress · `[DONE]` done · `[DONE — needs your eyes]` done but flagged · `[POSTPONED]` deliberately deferred · `[?]` needs a decision first

## C. Module A: StudyRoom Finder
*Free rooms in FMI / FSEGA, from the timetable plus live check-ins.*

### TODO-16 `[ ]` Buildings and rooms catalogue for FMI

`buildings` and `rooms` with code as it appears in the timetable, floor, capacity, sockets (prize), projector. Seeded from a hand-checked list.

*MVP: list and filters need these attributes, which the timetable does not contain.*

**What deciding it needs:** someone walks the FMI buildings (Mathematica, Centrul de Calcul, …) or gets the list from the faculty.

### TODO-17 `[ ]` FMI timetable importer

Python adapter in `scripts/schedule-import/` that fetches the published FMI timetable, parses room, day, hours, week parity and semester, and loads a new `room_schedule` batch with sanity checks (CLAUDE.md §3.3). Runs on a GitHub Actions cron (e.g. nightly, plus manual trigger).

*MVP "Stare calculată din orar". Risk from the idea: formats differ by faculty and change, so the adapter is isolated and there is a manual fallback (TODO-18).*

**What deciding it needs:** OQ-8. Start by saving a few real timetable pages as fixtures and writing parser tests against them.

### TODO-18 `[ ]` Admin overrides for the timetable

Admins add/cancel/move an occupation for a room and time range; overrides are stored separately and win over imported rows.

*Risk mitigation "fallback manual (adminii pot corecta datele)".*

**What deciding it needs:** OQ-4.

### TODO-19 `[ ]` Compute room status

SQL function/view returning, per room, `free` / `occupied` / `free until HH:MM` / `unknown` for a given instant, from schedule + overrides + active check-ins (+ reports once TODO-23 exists). Evaluated in `Europe/Bucharest`.

*MVP core of Module A. See CLAUDE.md §3.4 and §4.*

**What deciding it needs:** how to treat holidays and the exam session (no timetable means "unknown", not "free"?).

### TODO-20 `[ ]` Room list with filters

List with current status; filters for building, capacity, free for at least N hours, sockets, projector. Live updates via Realtime on check-ins.

*MVP "Listă de săli" + "Filtre".*

**What deciding it needs:** after TODO-19.

### TODO-21 `[ ]` Building map / floor plan

Plan of the building with rooms coloured by status.

*MVP "Hartă sau plan al clădirii".*

### TODO-22 `[ ]` Room check-in

"Sunt aici": a student checks in to a room, optionally with free seats left and which amenities (sockets, projector) are in use. Auto-expires (default 2 h), manual check-out.

*MVP "Check-in în sală".*

**What deciding it needs:** expiry length, and whether a check-in needs location proof (probably not for MVP).
